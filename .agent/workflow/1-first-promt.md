# Задача

Доработать и упаковать Python-бота мониторинга слотов VFS Global Italy (Казахстан) для запуска как фонового Docker-воркера в Coolify. Браузер не запускается внутри контейнера: бот подключается к уже развёрнутому сервису browserless по WebSocket.

Исходный файл: `bot.py` (Playwright async, aiohttp/requests, OpenAI, Telegram Bot API). Сейчас он подключается к локальному Chrome через `connect_over_cdp("http://localhost:9222")`. Нужно перевести его на browserless и сделать пригодным для непрерывной работы на сервере.

# Что нужно сделать

## 1. Конфигурация через переменные окружения
Удалить из кода все секреты и читать из `os.environ`:
- `BROWSERLESS_WS` (например `ws://host:3000/chromium?token=...&timeout=86400000`)
- `OPENAI_API_KEY`
- `TG_BOT_TOKEN`
- `TG_CHAT_IDS` (через запятую)
- `MAIN_EMAIL`, `MAIN_PASSWORD`
- `DONOR_ACCOUNTS` (JSON: `[{"email":"...","password":"..."}]`)
- `USER_DATA_JSON` (JSON с данными заявителя вместо текущих плейсхолдеров `ВСТАВЬ_...`)
Необязательные, со значениями по умолчанию: `ROUNDS_BEFORE_ROTATION=3`, `ROUND_DELAY_MIN=180`, `ROUND_DELAY_MAX=300`, `CITY_DELAY_MIN=15`, `CITY_DELAY_MAX=25`, `LOG_LEVEL=INFO`.
При отсутствии обязательной переменной бот завершается с понятным сообщением, какой именно нет. Добавить `.env.example` без реальных значений и `.gitignore` с `.env`.

## 2. Подключение к browserless
- Заменить `connect_over_cdp("http://localhost:9222")` на подключение к `BROWSERLESS_WS`.
- Реализовать цикл переподключения: если сессия оборвана (`browser.is_connected() == False`, исключения подключения), подождать и подключиться заново, восстановив состояние (страница логина, текущий донор).
- Проверить, какой метод корректен для используемой версии browserless (`connect_over_cdp` или `chromium.connect`), и выбрать рабочий.
- Оба фоновых таска (`telegram_handler`, `monitor_routine`) должны корректно завершаться и перезапускаться при переподключении, без утечки задач.

## 3. Надёжность
- Заменить блокирующие вызовы `requests` внутри async-кода на `httpx.AsyncClient` (или `asyncio.to_thread`). Цикл событий не должен подвисать.
- Ответы Telegram и OpenAI: таймауты, ретраи с backoff, никакого падения бота из-за ошибки внешнего API.
- Заменить `print`-лог на модуль `logging` (формат со временем, уровень из `LOG_LEVEL`). В логах не должно быть паролей, токенов и ключей.
- Обработка сигналов SIGTERM/SIGINT: корректно закрыть браузер и остановить задачи.
- Убрать `winsound` (Linux) либо оставить как необязательный.
- Сохранять состояние ротации (индекс донора, счётчики) хотя бы в памяти между переподключениями; при желании в файл на volume.

## 4. Логика завершения после находки слота
Сейчас после находки слота скрипт логинится в основной аккаунт и завершает цикл, после чего сессия browserless закрывается, а слот теряется. Предложить и реализовать безопасный вариант:
- отправить уведомление в Telegram со скриншотом;
- не закрывать сессию, оставить браузер на основном аккаунте и продолжить отвечать на сообщения в Telegram;
- по возможности выдать ссылку или инструкцию для просмотра живой сессии browserless (live view / debugger), чтобы человек мог завершить запись сам;
- предусмотреть автоматическую паузу мониторинга на настраиваемое время, затем возврат к мониторингу.
Автоматическое оформление записи не делать без отдельного подтверждения.

## 5. Docker и развёртывание в Coolify
- `Dockerfile` на `python:3.12-slim`, без установки браузеров (`playwright install` не нужен), запуск `python -u bot.py`, непривилегированный пользователь.
- `requirements.txt` с зафиксированными версиями.
- `README.md` на русском: переменные окружения, настройка browserless (`TOKEN`, `TIMEOUT`, `CONCURRENT`), пошаговое развёртывание в Coolify (Private Repository → Build Pack Dockerfile, без домена, отключённый Health Check, один Destination с browserless, галочка Is Literal для паролей), проверка запуска и типичные ошибки.

## 6. Тестирование
- Юнит-тесты (pytest) для чистой логики: чтение конфигурации, ротация доноров, определение бана 429 и ошибки 502 по тексту страницы, определение отсутствия слотов.
- Скрипт `check_connection.py`, который только подключается к browserless, открывает страницу логина VFS, делает скриншот и печатает статус. Он нужен для диагностики.

# Ограничения
- Не хардкодить секреты, не логировать их и не коммитить.
- Сохранить существующую логику: обход городов (Астана, Алматы, Усть-Каменогорск) в случайном порядке, категории «D Visa Study» и «Enrollment at Universities», паузы между городами и кругами, ротацию доноров при 429, паузу при 502, Telegram-бот с ответами по скриншоту через GPT-4o-mini.

- Не менять поведение без необходимости. Каждое существенное изменение кратко объяснять в комментарии или в описании коммита.
- Код должен работать на Linux в Docker.
